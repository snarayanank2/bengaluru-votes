# CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A PR into `main` is gated by tests; a push to `main` is tested (unless the identical tree just passed) and deployed to the production VPS with secrets installed from the GitHub `production` environment, with auto-rollback and a failure email.

**Architecture:** Small, unit-tested TypeScript helpers in `scripts/ci/` hold every decision (translate-gate, tag choice, tested-tree check, env render, alert body). Thin GitHub Actions workflows call them. `deploy/deploy.sh` stays the deploy and verification tool, gaining one distinct exit code. Rollout is staged: the deploy workflow is dispatch-only until the env file is proven identical to the box's, then a separate PR adds the `push` trigger.

**Tech Stack:** GitHub Actions, Node 22 + tsx, Vitest, bash, `gh` CLI, SendGrid HTTP API.

**Spec:** `docs/superpowers/specs/2026-11-04-ci-cd-design.md`

## Global Constraints

- Repo `snarayanank2/bengaluru-votes` is public, personal account. Default branch `main`.
- Workflow check required by the ruleset is named exactly `test`.
- PR workflow trigger is `pull_request` only, never `pull_request_target`; PR jobs have `permissions: contents: read` and no secrets.
- Deploy runs only in environment `production`, restricted to branch `main`; `concurrency: production-deploy`, `cancel-in-progress: false`.
- Third-party actions pinned by full commit SHA. No PR-controlled text (title, branch, body) interpolated into shell.
- Tags: annotated, `vYYYY.MM.DD`, then `.2`, `.3`. Pushed with `GITHUB_TOKEN` (`contents: write` on the deploy job only).
- Env file target `/etc/bengaluru-votes/.env.production`, mode 600, root; previous kept as `.env.production.prev`; values travel over SSH stdin, never argv. Forbidden keys: `OTP_TEST_SINK`, `SENDS_DISABLED`.
- `translate --check` gate passes only if the sole stale entry is `content/pages/kn/privacy.md`.
- Job timeout for the test job: 5 minutes. Postgres service image: `postgres:16`. CI env: `SITE_ORIGIN=https://bengaluruvotes.opencity.in`, test DB `bv_test`.
- Tested-tree artifact name `tested-tree-<git tree hash>`; counts only if from workflow `ci.yml`, event `pull_request`, conclusion `success`, base `main`, head repo == this repo, unexpired. Retention 30 days.
- No review rule and no CODEOWNERS (Siva's decision). Alert address in env var `DEPLOY_ALERT_EMAIL`; mail via SendGrid with `SENDGRID_API_KEY`, `SENDGRID_FROM_EMAIL`.
- Anything that changes GitHub settings, pushes to `main`, or touches the VPS needs Siva's go-ahead at that step (Tasks 10-12).

## Review Focus

- A secret value that is empty, or contains a newline: render must fail before any SSH (Task 5).
- Two merges the same day, or a re-run of the same commit: the tag is the next free suffix, and an existing tag for this commit is reused, not duplicated (Task 3).
- A forged `tested-tree-*` artifact from a fork or another branch must not skip tests (Task 4).
- A key on the box that the manifest lacks must surface in the dry-run compare, not be dropped (Task 5).
- SendGrid being down or misconfigured must not mask the original failure (Task 7).
- Failure before `up -d` must not trigger rollback; failure after must (Task 1).

## File Structure

- `deploy/deploy.sh` (modify) — exit 3 for failures after `up -d`.
- `deploy/env.production.manifest` (create) — contract of keys.
- `deploy/install-env.sh` (create) — atomically installs stdin as the box's env file.
- `scripts/ci/translate-gate.ts`, `tag.ts`, `tested-tree.ts`, `env-render.ts`, `alert.ts` (create) — pure logic plus a small CLI `main` each.
- `scripts/ci/bootstrap-env.ts` (create) — one-time load of the box's values into the GitHub environment.
- `tests/unit/ci/*.test.ts`, `tests/unit/deploy-script.test.ts` (create).
- `.github/actions/gate/action.yml`, `.github/workflows/ci.yml`, `.github/workflows/deploy.yml`, `.github/rulesets/main.json` (create).
- Docs: `docs/architecture.md` §13/§14.4, `deploy/runbook.md` "Deploying", `.claude/skills/deploy-vps/SKILL.md`, `AGENTS.md` if it mentions manual deploys.

### Task 9: deploy workflow (dispatch only)

**Files:** Create `.github/workflows/deploy.yml`

**Interfaces:**
- Trigger for now: `workflow_dispatch` with input `action` (`deploy-head`, `redeploy-current`, `deploy-tag`, `rollback`) and optional `tag`. A comment marks where `push: branches: [main]` is added in Task 12.
- Jobs: `decide` (no secrets: runs `tested-tree.ts`; for dispatch of an existing tag it reports tested=true), `test` (needs decide, `if tested == false`, same gate), `deploy` (needs both, environment `production`, `permissions: contents: write`, `concurrency: production-deploy`). Deploy steps in order: write SSH key and pinned `known_hosts` from environment secrets `VPS_SSH_KEY`, `VPS_HOST_KEY` and variable `VPS_HOST`, plus a generated `~/.ssh/config` alias `vps`; run `env-render.ts render` (fails before SSH if invalid); `chooseTag` then `git tag -a` and push if `create`; `deploy/install-env.sh`; `deploy/deploy.sh production <tag>`; on exit code 3 run `deploy/deploy.sh production --rollback`; final `if: failure()` step runs `alert.ts` with the right kind, then the job stays red. A `test` job failure on `main` also runs `alert.ts` (`test-failed`). All `${{ }}` values reach scripts through `env:`, never inline in `run:`.

- [ ] **Step 1:** Write it. **Step 2:** `actionlint` — no findings. **Step 3:** A grep check that no `run:` block contains `${{ github.event` or `${{ inputs.` (command: `grep -nE 'run:.*\$\{\{ (github\.event|inputs)' .github/workflows/*.yml` returns nothing; check multi-line `run: |` blocks by eye).
